# Lean Agent Workflow 0.2.0

一个短流程的产品开发 skill：把工作拆成真实的用户切片，只在关键节点做充分验证，把跨模块和全量回归集中到模块或阶段收口时完成。

## 流程

1. **定一个目标**：写清用户结果、范围、风险和完成条件。只有范围、权限、数据归属或外部副作用会改变时才追问。
2. **实现垂直切片**：把用户动作、状态变化、持久化、错误反馈放在同一个切片里。
3. **按风险验证**：S0/S1 做定向检查；S2 做成功路径加失败/恢复；S3 做关键链路、权限或外部副作用验证。
4. **留下短记录**：记录目标、改动、检查、状态和边界，使用 `PASS`、`PARTIAL`、`FAIL`、`NOT TESTED`。

## 关键节点

保存恢复、账号/项目隔离、版本和资产绑定、真实 provider 任务与预算、导出和其他不可逆写入，发生改动时必须立即验证。普通样式、文案和低风险局部交互只需轻量检查。跨模块和完整回归放到一个功能块或发布阶段完成。

## 证据边界

mock 或确定性适配器只能证明本地编排，不能证明真实 provider 的质量、额度、账单或发布结果。完成声明必须有对应命令、浏览器/API步骤或产物证据；没有证据就保留为 `PARTIAL` 或 `NOT TESTED`。

## 显式调用

该 skill 默认不自动注入上下文，可使用 `$lean-agent-workflow` 显式调用。完整验收行格式和浏览器/API证据规则分别见 `references/acceptance-matrix.md` 与 `references/e2e-evidence.md`。
